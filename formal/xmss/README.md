# XMSS security formalization

This Lean project formalizes the classical random-oracle security game from `doc/xmss/main.tex`. It pins Lean and VCVio so that the game, its query accounting, and its probability semantics are reproducible.

The adversary has access to the shared random oracle and a signing oracle. Signing responses are logged. A repeated signing epoch makes the transcript invalid, and the strong-forgery check rejects only an exact replay of the signature returned for the claimed message and epoch. The random-oracle query bound is imposed after the adversary and signing oracle have been simulated, so it covers key generation, adversarial queries, signing, and final verification.

`XmssSecurity.Encoding` implements the concrete little-endian digest parser and proves its injectivity, target-sum incomparability, and the exact 99-edge verification cost. `XmssSecurity.Tweak` implements the 128-bit tweak layout, gives typed addresses to every chain, leaf, Merkle, and message-encoding hash call, and proves that their serialized tweaks are injective. `XmssSecurity.Serialization` and `XmssSecurity.ConcreteHash` serialize concrete values into bytes, construct the exact `tweak || P || payload` random-oracle inputs, prove the required injectivity and domain-separation properties, and define the four concrete hash-call combinators. `XmssSecurity.CacheView` interprets those calls deterministically in a final lazy-oracle cache, including the epoch-dependent left-right ordering of authentication nodes, and proves injectivity of every concrete input family. `XmssSecurity.Wots`, `XmssSecurity.Merkle`, and `XmssSecurity.ForgeryCases` give checked deterministic classifications of both same-epoch strong forgeries and fresh-epoch forgeries into 175 explicitly indexed bad-event slots. `XmssSecurity.ConcreteForgery` instantiates both classifiers with the concrete cache view and derives the structural strong-forgery alternatives from concrete messages and signatures. `XmssSecurity.ConcreteVerify` transcribes verification over any monad providing the hash oracle, `XmssSecurity.ConcreteKeygen` constructs the complete WOTS and Merkle public key, `XmssSecurity.ConcreteSign` constructs one rejection-sampling attempt and every successful signature, and `XmssSecurity.ConcreteScheme` packages the finite concrete game. `XmssSecurity.CacheVerify` states deterministic verification semantics, `XmssSecurity.CacheReplay` proves deterministic final-cache semantics for verification, key generation, and a signing attempt, and `XmssSecurity.ConcreteCorrectness` proves that every successful honest signing attempt verifies against the cached key-generation root, including all WOTS chains and all 32 Merkle levels. `XmssSecurity.DetailedExecution` retains the key pair, signing log, forgery, verifier result, and final cache without changing the win probability, including the structural hash-query bound. `XmssSecurity.OutcomeClassification` proves that every cache-consistent winning transcript selects one of the 175 concrete events. `XmssSecurity.ConcreteExecution` proves cache growth, replay against later cache extensions, actual key-generation and verification consistency, and successful-call signing consistency. `XmssSecurity.SigningLogReplay` lifts successful-call replay through arbitrary adaptive adversary executions, proves that every supported detailed outcome is cache-consistent, and derives the unconditional probability union bound over all 175 events. `XmssSecurity.ConcreteEventCollision` proves that every encoding, suffix, leaf, or Merkle event contains two distinct serialized random-oracle inputs with equal cached digests, leaving only chain events as hidden-preimage cases. `XmssSecurity.RandomOracle` proves fixed-output and 128-bit truncated-output bounds for an empty or pre-populated lazy random-oracle cache, including a finite-target union bound. `XmssSecurity.HiddenValue` proves adaptive first-hit bounds for one or up to 175 independent hidden 128-bit values, including strategies selected by prior public randomness. `XmssSecurity.IndexedHiddenValue` proves that adaptive probes against a uniform epoch-indexed digest table cost `q / 2^128` independently of the number of epochs, including when public randomness selects the probes. `XmssSecurity.Execution` retains the final lazy random-oracle cache and proves that this does not change the signature-game advantage. `XmssSecurity.MixedOracle` proves the fixed-target bounds directly for the full game, where arbitrary public sampling is interleaved with the bounded hash queries. `XmssSecurity.FreshTarget`, `XmssSecurity.AdaptiveFreshTarget`, and `XmssSecurity.PrefixTarget` prove that a fresh query colliding with a cached 128-bit target costs `q / 2^128`, even when each query adaptively selects its own target after a randomized prefix. `XmssSecurity.QueryBoundSupport` transfers a whole-program query bound to every supported continuation, and `XmssSecurity.ConcreteEventProbability` turns temporal orientation of a concrete bad event after key generation into its `q / 2^128` bound. `XmssSecurity.CacheQuerySupport` converts zero-query and one-query structural bounds into cache absence and cache uniqueness. `XmssSecurity.HashAddress`, `XmssSecurity.ConcreteQueryBound`, `XmssSecurity.TreeQueryBound`, and `XmssSecurity.MerkleQueryBound` define concrete 32-byte address classes and prove that the full height-32 key-generation tree queries every leaf, chain-step, and Merkle-node address at most once without expanding the tree. `XmssSecurity.KeygenCache` transfers these bounds through cache-neutral key sampling to the actual key-generation cache. `XmssSecurity.QueryPresence` proves that supported leaf and tree executions cache the exact honest leaf input reconstructed against any later cache extension and that every honest WOTS public key remains stable in all later caches. `XmssSecurity.ChainQueryPresence` locates every exact honest internal WOTS-chain input in the full key-generation tree, proves competing payloads absent at that typed address, and proves all honest intermediate chain values stable in later caches. `XmssSecurity.MerkleQueryPresence` locates every valid internal Merkle input in the key-generation cache and proves that its child values remain stable in later cache extensions. `XmssSecurity.DetailedQueryPresence` proves that successful verification caches the exact forged leaf input. `XmssSecurity.FreshLeafOrientation` combines these facts to orient every fresh-epoch leaf event as a fresh random-oracle collision against the leaf fixed by key generation. `XmssSecurity.LeafEventProbability` proves the same orientation for honestly signed epochs and derives the complete leaf-event bound `q / 2^128`. `XmssSecurity.SuffixEventProbability` identifies the precise forged recovery-chain query in both fresh and honestly signed executions and proves `q / 2^128` for each of the 99 suffix-collision slots. `XmssSecurity.MerkleEventProbability` identifies every verifier authentication-node query, handles its epoch-dependent child order, and proves `q / 2^128` for each of the 32 Merkle slots. `XmssSecurity.EncodingQueryBound`, `XmssSecurity.EncodingPrehitProbability`, and `XmssSecurity.EncodingEventProbability` prove the complete adaptive encoding-event bound, including signer and adversary random-oracle queries. `XmssSecurity.PublicRootUniformity` proves that the concrete public root is uniform independently of the entire secret table after the private key-generation cache is hidden, and derives adaptive fixed-chain seed-guessing security after public-key exposure. `XmssSecurity.SecurityBudget` proves that the weighted bad events fit below `q / 2^120`. `XmssSecurity.MainTheorem` leaves only the WOTS chain-origin probability bound in its single intentional `sorry`, while deriving the 120-bit theorem as a checked corollary.

`XmssSecurity.ChainEventDecomposition` proves that each of the 42 chain events is either an exact honest key-generation chain-value guess or an already bounded fresh collision, and traces every positive guessed value to its preceding key-generation query. `XmssSecurity.ChainOriginProbability` retains the private key-generation cache, proves that projecting it away recovers the detailed game, and lifts the chain reduction through that experiment. `XmssSecurity.ChainInputTrace` records attacker-visible hash and signing actions without exposing signer-internal hash calls, proves exact projection back to the source game, and charges every supported trace to the global hash-query budget while reserving one query for final verification. `XmssSecurity.ChainTrajectoryUniformity` exposes every value of one WOTS trajectory, proves exact replay against the cache, proves that each next typed chain address is fresh, and derives that an isolated full trajectory is jointly uniform. `XmssSecurity.ChainTrajectoryComposition` proves that one epoch's trajectory cannot populate another epoch's typed addresses, composes the cache-conditional result over every pairwise-distinct finite epoch list, and derives exact joint probability for the full opaque epoch enumeration without constructing its `2^32` list cells. `XmssSecurity.ChainHiddenTable` normalizes secret seeds and positive chain origins into one table indexed by epoch and digit, parses direct chain-input probes, includes the final forgery as the reserved probe, proves that every winning origin event hits this table with at most `q` probes, and connects the table to the one-pass trajectory computation. `XmssSecurity.SecretTableUniformity` proves that the complete epoch table of secret WOTS seeds for any fixed chain is jointly uniform and derives its adaptive `q / 2^128` equality-probe bound. `XmssSecurity.SecurityBudget` also proves the weighted 217-term budget that allows each chain event one hidden-value term plus one collision term while remaining below `q / 2^120`.

The current first security target uses a fully concrete one-attempt signer: it samples one 192-bit randomness value, returns the corresponding signature when the target-sum decoder accepts, and otherwise returns `none`. Successful attempts are proved correct against the generated root. The specification's potentially unbounded rejection-sampling repetition cannot be represented directly by finite `OracleComp` syntax and remains a later semantic refinement. Every supported game execution now satisfies the complete final-cache consistency predicate, so a win unconditionally selects one of the 175 concrete events. The single intentional `sorry` is restricted to preserving the entropy of a WOTS seed or intermediate chain value through adaptive post-key-generation oracle and signing interactions. The encoding, leaf, suffix, and Merkle bounds, public-root independence, and every deterministic chain extraction and provenance obligation are checked.
