# XMSS security formalization

This Lean project formalizes the classical random-oracle security game from `doc/xmss/main.tex`. It pins Lean and VCVio so that the game, its query accounting, and its probability semantics are reproducible.

The adversary has access to the shared random oracle and a signing oracle. Signing responses are logged. A repeated signing epoch makes the transcript invalid, and the strong-forgery check rejects only an exact replay of the signature returned for the claimed message and epoch. The random-oracle query bound is imposed after the adversary and signing oracle have been simulated, so it covers key generation, adversarial queries, signing, and final verification.

`XmssSecurity.Encoding` implements the concrete little-endian digest parser and proves its injectivity, target-sum incomparability, and the exact 99-edge verification cost. `XmssSecurity.Tweak` implements the 128-bit tweak layout, gives typed addresses to every chain, leaf, Merkle, and message-encoding hash call, and proves that their serialized tweaks are injective. `XmssSecurity.Serialization` and `XmssSecurity.ConcreteHash` serialize concrete values into bytes, construct the exact `tweak || P || payload` random-oracle inputs, prove the required injectivity and domain-separation properties, and define the four concrete hash-call combinators. `XmssSecurity.CacheView` interprets those calls deterministically in a final lazy-oracle cache, including the epoch-dependent left-right ordering of authentication nodes, and proves injectivity of every concrete input family. `XmssSecurity.Wots`, `XmssSecurity.Merkle`, and `XmssSecurity.ForgeryCases` give checked deterministic classifications of both same-epoch strong forgeries and fresh-epoch forgeries into 175 explicitly indexed bad-event slots. `XmssSecurity.ConcreteForgery` instantiates both classifiers with the concrete cache view and derives the structural strong-forgery alternatives from concrete messages and signatures. `XmssSecurity.ConcreteVerify` transcribes verification over any monad providing the hash oracle, `XmssSecurity.ConcreteKeygen` constructs the complete WOTS and Merkle public key, `XmssSecurity.ConcreteSign` constructs one rejection-sampling attempt and every successful signature, and `XmssSecurity.ConcreteScheme` packages the finite concrete game. `XmssSecurity.CacheVerify` states deterministic verification semantics, `XmssSecurity.CacheReplay` proves deterministic final-cache semantics for verification, key generation, and a signing attempt, and `XmssSecurity.ConcreteCorrectness` proves that every successful honest signing attempt verifies against the cached key-generation root, including all WOTS chains and all 32 Merkle levels. `XmssSecurity.DetailedExecution` retains the key pair, signing log, forgery, verifier result, and final cache without changing the win probability, including the structural hash-query bound. `XmssSecurity.OutcomeClassification` proves that every cache-consistent winning transcript selects one of the 175 concrete events. `XmssSecurity.ConcreteExecution` proves cache growth, replay against later cache extensions, actual key-generation and verification consistency, and successful-call signing consistency. `XmssSecurity.SigningLogReplay` lifts successful-call replay through arbitrary adaptive adversary executions, proves that every supported detailed outcome is cache-consistent, and derives the unconditional probability union bound over all 175 events. `XmssSecurity.ConcreteEventCollision` proves that every encoding, suffix, leaf, or Merkle event contains two distinct serialized random-oracle inputs with equal cached digests, leaving only chain events as hidden-preimage cases. `XmssSecurity.RandomOracle` proves fixed-output and 128-bit truncated-output bounds for an empty or pre-populated lazy random-oracle cache, including a finite-target union bound. `XmssSecurity.HiddenValue` proves adaptive first-hit bounds for one or up to 175 independent hidden 128-bit values, including strategies selected by prior public randomness. `XmssSecurity.IndexedHiddenValue` proves that adaptive probes against a uniform epoch-indexed digest table cost `q / 2^128` independently of the number of epochs, including when public randomness selects the probes. `XmssSecurity.Execution` retains the final lazy random-oracle cache and proves that this does not change the signature-game advantage. `XmssSecurity.MixedOracle` proves the fixed-target bounds directly for the full game, where arbitrary public sampling is interleaved with the bounded hash queries. `XmssSecurity.FreshTarget`, `XmssSecurity.AdaptiveFreshTarget`, and `XmssSecurity.PrefixTarget` prove that a fresh query colliding with a cached 128-bit target costs `q / 2^128`, even when each query adaptively selects its own target after a randomized prefix. `XmssSecurity.QueryBoundSupport` transfers a whole-program query bound to every supported continuation, and `XmssSecurity.ConcreteEventProbability` turns temporal orientation of a concrete bad event after key generation into its `q / 2^128` bound. `XmssSecurity.SecurityBudget` proves that 175 such events fit below `q / 2^120`. `XmssSecurity.MainTheorem` isolates the unfinished temporal-orientation and chain-preimage event bounds in `xmss_badEvent_probability_le`, the single intentional `sorry`, and derives the 120-bit theorem as a checked corollary.

The current first security target uses a fully concrete one-attempt signer: it samples one 192-bit randomness value, returns the corresponding signature when the target-sum decoder accepts, and otherwise returns `none`. Successful attempts are proved correct against the generated root. The specification's potentially unbounded rejection-sampling repetition cannot be represented directly by finite `OracleComp` syntax and remains a later semantic refinement. Every supported game execution now satisfies the complete final-cache consistency predicate, so a win unconditionally selects one of the 175 concrete events. The remaining game proof must bound each individual event by `q / 2^128`, using the checked collision extraction and indexed hidden-value lemmas.
